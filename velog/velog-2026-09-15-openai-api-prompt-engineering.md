# OpenAI API와 System Prompt로 문서 토픽 이름 생성하기

## 들어가며

LLM을 활용할 때 중요한 것은 API를 한 번 호출하는 것만이 아니다. 모델에게 어떤 역할을 부여할지, 대화 맥락을 어떻게 전달할지, 원하는 결과 형식을 어떻게 제한할지를 설계해야 한다. 이번 학습에서는 OpenAI API 기본 호출과 System Prompt를 이용한 문서 토픽 이름 생성을 실습했다.

## 메시지와 역할

대화는 `messages` 목록으로 전달하며, 각 메시지는 역할과 내용을 가진다.

- `system`: 모델의 역할, 규칙, 말투, 제한사항
- `user`: 사용자의 질문이나 작업 대상
- `assistant`: 이전 모델 응답

```python
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="사용할 모델명",
    messages=[
        {"role": "system", "content": "쉽고 간결하게 설명하는 선생님이다."},
        {"role": "user", "content": "파이썬의 장점을 설명해줘."},
    ],
)

answer = response.choices[0].message.content
```

응답 객체에서는 생성된 내용뿐 아니라 `finish_reason`과 토큰 사용량도 확인할 수 있다.

## 대화 맥락 유지

API는 이전 대화를 자동으로 기억하지 않으므로, 대화 내용을 `messages`에 계속 저장해 다음 요청에 함께 전달해야 한다.

```python
messages = [
    {"role": "user", "content": "너는 어떤 역할이야?"},
    {"role": "assistant", "content": "나는 학습을 돕는 조교야."},
    {"role": "user", "content": "방금 내 질문을 요약해줘."},
]
```

대화가 길어지면 토큰 사용량과 비용이 증가하므로, 실제 서비스에서는 대화 요약이나 필요한 정보만 남기는 전략이 필요하다.

## 스트리밍 응답

스트리밍을 사용하면 답변이 모두 생성될 때까지 기다리지 않고 조각 단위로 받을 수 있다. 긴 답변이나 사용자에게 생성 과정을 바로 보여줘야 하는 인터페이스에 활용할 수 있다.

```python
stream = client.chat.completions.create(
    model="사용할 모델명",
    messages=[{"role": "user", "content": "AI 활용 방법을 설명해줘."}],
    stream=True,
)

pieces = []
for chunk in stream:
    piece = chunk.choices[0].delta.content
    if piece:
        pieces.append(piece)
```

## System Prompt로 토픽 이름 제한하기

뉴스 문서의 토픽 이름을 생성할 때 단순히 “이름을 지어줘”라고 요청하면 모델이 원문에 없는 내용을 추가하거나 형식을 일정하게 지키지 않을 수 있다. 따라서 작업 목적과 출력 규칙을 명시한다.

```python
system_prompt = """
너는 뉴스 문서의 핵심 주제를 파악하는 분류 전문가다.
- 2~5어절의 간결한 한국어 명사형으로 작성한다.
- 문서에 실제로 드러난 내용만 반영한다.
- 설명, 번호, 따옴표, 마침표는 출력하지 않는다.
- 토픽 이름만 한 줄로 출력한다.
"""
```

이후 대표 문서를 사용자 메시지로 전달하면 BERTopic이 찾은 토픽을 사람이 읽기 쉬운 이름으로 정리할 수 있다.

## 프롬프트 결과 평가

프롬프트는 자연스러운 답변 하나를 얻는 데서 끝나지 않는다. 같은 조건에서 반복해도 결과가 일정한지, 입력 표현이 조금 바뀌어도 규칙을 지키는지 확인해야 한다.

평가 기준의 예시는 다음과 같다.

- 원문 근거성: 문서에 없는 내용이 추가되지 않았는가?
- 형식 준수: 어절 수와 명사형 조건을 지키는가?
- 일관성: 같은 주제에 비슷한 이름을 생성하는가?
- 강건성: 입력 순서나 표현이 바뀌어도 결과가 크게 흔들리지 않는가?

## 마무리

LLM 활용의 핵심은 단순한 API 호출보다 역할, 맥락, 출력 형식, 금지사항, 평가 기준을 설계하는 데 있다. 문서 군집화로 데이터의 주제 구조를 찾고 LLM으로 토픽 이름을 정리하면, 비정형 문서를 탐색하고 설명하는 분석 흐름을 만들 수 있다.
