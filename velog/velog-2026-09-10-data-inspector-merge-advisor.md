# 데이터 결합 전에 Grain과 Key를 확인하는 이유

## 들어가며

데이터 분석에서 가장 위험한 오류 중 하나는 서로 다른 데이터의 의미를 확인하지 않고 공통 컬럼만으로 결합하는 것이다. `merge()`가 실행되었다고 해서 결합이 올바르게 된 것은 아니다.

## 분석 질문에서 시작하기

분석 전에 무엇을 알고 싶은지, 한 행은 무엇을 의미하는지, 분석 기간과 범위는 무엇인지, 어떤 지표와 집계가 필요한지를 정의해야 한다.

분석 목적과 지표가 정해져야 최종 DataFrame의 Grain과 필요한 Key를 결정할 수 있다.

## 안전한 데이터 결합 workflow

```text
INSPECT
→ VALIDATE
→ DEFINE
→ PLAN
→ 사용자 승인
→ EXECUTE
→ VERIFY
→ LOG
```

검사 단계에서는 파일 형식, Excel 시트, shape, 컬럼, dtype, 결측치, 중복, 공백, 날짜 변환 후보를 확인한다. 이 단계에서는 원본을 수정하지 않고 진단 결과와 추천 사항만 반환한다.

## Grain과 Key

예를 들어 승하차 데이터의 한 행이 날짜 × 호선 × 역이라면, 혼잡도 데이터는 요일 × 호선 × 역 × 시간대일 수 있다. 공통 컬럼인 호선과 역만으로 결합하면 동일 Key가 여러 번 반복되어 N:N 관계가 발생할 수 있다.

```text
목표 DataFrame의 Grain 확인
→ 원본별 Grain 확인
→ Key 후보와 중복률 확인
→ 필요한 수준으로 groupby·agg
→ 결합 관계 검증
```

Key와 Grain은 자동으로 확정하지 않고 후보와 근거, 위험을 함께 검토해야 한다. 값이 유일하다는 사실만으로 의미적으로 올바른 Key라고 할 수 없기 때문이다.

## 병합 후 검증

```python
merged_df = left_df.merge(
    right_df,
    on=["호선", "역명"],
    how="left",
    validate="1:1"
)
```

실제 관계가 1:1인지 확신할 수 없다면 먼저 중복과 Grain을 검사해야 한다. 병합 후에는 행 수 변화, 매칭률, 미매칭 Key, 중복 증가, 데이터 손실을 확인한다.

## 마무리

자동화의 목표는 분석가의 판단을 없애는 것이 아니다. 반복적인 구조와 품질 확인을 줄이고, 데이터의 의미와 결합 위험을 사람이 판단할 수 있도록 근거를 제공하는 것이 Data Inspector의 핵심이다.
