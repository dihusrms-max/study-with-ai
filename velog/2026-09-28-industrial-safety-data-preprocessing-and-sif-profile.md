# 산업재해 데이터 전처리와 SIF 원본 구조 점검

산업재해 RAG 프로젝트를 진행하면서 모든 데이터를 하나의 검색 코퍼스로 취급하지 않고, 목적에 따라 나누어야 한다는 점을 다시 확인했다. 업종·규모별 통계는 대시보드와 SQL 분석에, SIF 고위험요인 아카이브는 사고사례 검색에 사용한다. 산업안전 용어사전은 검색어 확장에 보조적으로 활용하고, 공개자료 URL 목록은 사고보고서 원문이 아니므로 사례 근거로 사용하지 않는다.

이번 작업에서는 통계 자료를 분석하기 쉬운 형태로 전처리하고, SIF XLSX는 원본을 수정하지 않은 채 시트 구조와 품질 항목을 점검했다.

## 1. 통계 데이터의 wide 형식을 long 형식으로 변환

업종과 사업장 규모가 열로 펼쳐진 통계 자료는 업종·규모·지표·값 형태의 long 구조로 변환했다. 이 형식은 지표를 구분해 집계하거나 여러 통계 자료를 같은 업종·규모 기준으로 비교할 때 다루기 쉽다.

전처리에서는 업종명과 규모 구간의 표기 공백만 정리하고, 원본 분류 표기도 함께 보존했다. 원래 값과 정리된 값을 같이 남겨야 변환 결과를 추적하고 차이를 검토할 수 있기 때문이다.

| 자료 | 원본 행 | 결과 행 | 품질 확인 |
| --- | ---: | ---: | --- |
| 업종·규모별 사고재해자수 | 30 | 300 | 값 결측 0, 중복 업종 키 0 |
| 업종·규모별 사고사망자수 | 30 | 300 | 값 결측 0, 중복 업종 키 0 |
| 업종·규모별 사업장수 | 30 | 300 | 값 결측 0, 중복 업종 키 0 |
| 업종·규모별 사망만인율 | 30 | 300 | 값 결측 14, 중복 업종 키 0 |

규모별 장기 사고사망자 추이 자료는 2004년부터 2025년까지 연도·규모 단위로 정리했다. 원본 10행이 220행으로 변환됐으며, 이 자료에는 산업중분류가 없으므로 산업별 통계와 구분해 장기 추세용으로 사용한다.

## 2. 결측값을 임의로 0으로 바꾸지 않기

사망만인율의 결측값은 14건이었다. 이를 0으로 채우면 실제 값이 0인 경우와 원자료가 비어 있는 경우를 구분할 수 없게 된다. 값이 비어 있는 이유와 분모·자료 제공 여부를 확인하기 전까지 결측을 그대로 유지했다.

전처리는 값을 보기 좋게 만드는 과정에 그치지 않는다. 값의 의미를 보존하고, 어떤 규칙을 적용했는지 설명할 수 있어야 분석 결과도 해석할 수 있다.

## 3. 용어사전과 공개자료 목록의 용도 구분

산업안전 용어사전은 표제어와 유의어 쌍으로 펼쳐 검색어 확장 실험에 사용할 수 있게 정리했다. 중복 쌍 728건을 제거한 뒤 총 7,169쌍을 남겼다. 용어사전은 질문 표현을 보완하는 용도이며 사고가 실제로 어떻게 발생했는지를 뒷받침하는 근거 문서로 사용하지 않는다.

공개자료 목록은 문서 유형, URL, 공개 범위와 설명을 담은 5행의 인덱스로 정리했다. 이 파일은 공개 사고보고서 본문 자체가 아니므로 SIF 사례 RAG 코퍼스와 분리해야 한다.

## 4. SIF XLSX를 읽기 전용으로 프로파일링

SIF 원본은 제조업 등과 건설업 시트의 구조가 서로 달라, 실제 사례를 검색 코퍼스로 준비하기 전에 시트별 구조와 행 식별자를 확인했다. 이번 프로파일링에서는 사고 서술 본문을 별도 결과 문서에 복사하지 않고 행 수, 필드, 결측과 중복 통계를 확인했다.

- 제조업 등 시트: 데이터 후보 2,573건, 연번 누락 0건, 중복 연번 0건, 중복 사례 행 0건
- 건설업 시트: 데이터 후보 3,459건, 연번 누락 0건, 중복 연번 0건, 중복 사례 행 0건
- 제조업 등 시트: 업종 대·중·소분류와 재해개요, 기인물, 고위험작업·상황 등 보유
- 건설업 시트: 공종, 작업명, 단위작업명, 재해종류 등 별도 필드 보유

두 시트 모두 연번은 고유했지만, 컬럼 구성이 다르다. 따라서 원본의 각 시트 구조는 보존하면서 검색에 필요한 공통 필드를 별도로 설계하는 접근이 필요하다. 사례 ID에는 시트 구분을 포함하고 원본 파일명, 시트명, 실제 Excel 행 위치도 함께 남기면 검색 결과를 원본에서 추적할 수 있다.

## 5. 데이터 목적에 따라 분석 경로 분리하기

이번 점검을 통해 프로젝트의 데이터 사용 경로를 다음처럼 나눴다.

```text
업종·규모 통계 → 정형 테이블 → SQL 분석·대시보드
SIF 사고사례 → 사례 문서 → 이용 조건 확인 후 RAG 색인 검토
안전 용어사전 → 유의어 쌍 → 검색어 확장 실험
공개자료 URL 목록 → 자료 탐색용 인덱스
```

정형 통계와 사고사례는 데이터의 단위와 목적이 다르다. 둘을 한 벡터 코퍼스에 넣기보다 각 목적에 맞는 처리와 검증을 적용하는 편이 적절하다.

## 6. 다음 단계와 남은 확인 사항

이번에 확인한 것은 통계 전처리 결과와 SIF 원본의 구조다. SIF의 임베딩, 벡터 색인, 실제 검색 평가는 아직 진행하지 않았다. 색인 전에 제공기관의 이용 조건과 임베딩·정제본·외부 배포 가능 범위를 확인해야 한다.

또한 평가 질문 20개의 관련 사례 ID 라벨은 비어 있다. 검색 결과를 자동 정답으로 간주하지 않고, 코퍼스가 확정된 후 사람이 원문과 질문의 관련성을 검토해 라벨을 작성해야 한다. 이후 동일한 질문으로 기본 검색과 용어 확장 검색을 비교하고 Hit@k와 MRR을 확인할 계획이다.

## 마무리

데이터 전처리에서는 long 형식 변환뿐 아니라 원본 분류 표기와 결측 의미를 보존하는 것이 중요했다. SIF 사례와 정형 통계, 용어사전은 서로 다른 역할을 가지므로 목적에 맞게 분리해야 한다. 특히 사례 RAG는 데이터 구조를 확인한 뒤에도 이용 조건과 검색 근거를 검증해야 다음 단계로 안전하게 진행할 수 있다.
