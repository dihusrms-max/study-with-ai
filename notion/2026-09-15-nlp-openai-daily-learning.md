# 2026-09-15 일일 학습 보고 — 문서 토픽 모델링과 LLM 프롬프트 설계

## 오늘 새롭게 이해한 것

- 문서 임베딩은 문장의 의미를 벡터로 변환해 유사한 문서끼리 비교할 수 있게 한다.
- KMeans는 군집 수를 직접 지정해야 하며, 엘보우와 실루엣 점수로 적절한 값을 검토할 수 있다.
- BERTopic은 임베딩·UMAP·HDBSCAN·c-TF-IDF를 연결해 문서의 토픽과 대표어를 추출한다.
- LLM API의 `system`, `user`, `assistant` 역할을 이용해 응답의 역할과 대화 맥락을 제어할 수 있다.
- 토픽 이름 생성 프롬프트에는 어절 수, 명사형, 원문 근거, 출력 형식을 구체적으로 지정해야 한다.
- 프롬프트 품질은 자연스러움뿐 아니라 결과의 일관성과 강건성으로 평가해야 한다.

## 아직 애매하거나 복습할 것

- UMAP과 HDBSCAN의 주요 파라미터를 조정하는 기준.
- BERTopic 토픽의 품질을 정량적으로 평가하는 방법.
- LLM이 생성한 토픽 이름의 정확성·일관성·원문 근거성을 평가하는 방법.
- 프롬프트 강건성을 측정할 테스트셋을 구성하는 방법.
- NER을 실제 문서 분류·정보 추출 업무에 적용하는 방법.
- API 호출 시 예외 처리와 토큰 사용량을 기록하는 방법.

## 직접 해본 것

- 뉴스 문서를 한국어 임베딩 벡터로 변환했다.
- KMeans와 DBSCAN으로 문서 군집화를 실습했다.
- 엘보우와 실루엣 점수로 군집 수를 검토했다.
- BERTopic에 한국어 임베더, Kiwi 토크나이저, UMAP, HDBSCAN을 연결했다.
- OpenAI API 기본 호출과 역할별 메시지 구조를 작성했다.
- `messages` 목록을 누적해 이전 대화를 이어가는 구조를 확인했다.
- 스트리밍 응답을 처리했다.
- 뉴스 문서의 토픽 이름을 생성하는 System Prompt를 작성했다.
- 프롬프트 엔지니어링과 NER의 활용 방향을 정리했다.

## 오늘의 핵심 인사이트

- 문서 군집화는 자동 정답 생성보다 데이터의 주제 구조를 탐색하는 과정에 가깝다.
- LLM의 결과 품질은 모델 자체뿐 아니라 역할·맥락·출력 형식·검증 기준의 설계에 영향을 받는다.
- 군집화로 주제를 찾고 LLM으로 이름을 붙이는 방식을 결합하면 비정형 문서를 사람이 이해하기 쉽게 정리할 수 있다.
