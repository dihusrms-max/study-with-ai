# 2026-09-28 일일 학습 기록

## 오늘 새롭게 이해한 것

### 1. 산업재해 데이터는 분석 목적에 맞게 분리해 다룬다

산업재해 프로젝트의 데이터는 한데 합쳐 RAG에 넣기보다 역할에 따라 나누어야 한다.

- 업종·사업장 규모별 재해 통계는 대시보드와 SQL 분석에 사용한다.
- SIF 고위험요인 아카이브는 유사 사고사례 검색을 위한 핵심 자료다.
- 산업안전 용어사전은 검색어 확장에 보조적으로 사용하며 사고의 근거 자료로 취급하지 않는다.
- 공개 자료 URL 목록은 원문 사고보고서가 아니므로 사고사례 RAG 코퍼스로 사용하지 않는다.

### 2. 통계 데이터의 전처리와 결측치 처리

업종·규모별 통계의 wide 형식을 업종·규모·지표·값 구조의 long 형식으로 변환하면 지표별 비교와 분석에 활용하기 쉽다. 전처리 시 업종명과 규모 표기의 공백만 정리하고 원본 분류 표기도 함께 보존해 변환 내역을 추적할 수 있게 했다.

결측된 사망만인율을 0으로 바꾸면 실제 0과 자료가 비어 있는 상태를 혼동할 수 있다. 따라서 이번 전처리에서는 결측값을 그대로 두고, 값이 없는 이유를 확인하기 전까지 임의로 채우지 않았다.

### 3. SIF 사례의 구조와 추적성

SIF 원본은 제조업 등과 건설업 시트의 컬럼 구조가 다르다. 공통 검색 스키마를 설계할 때 원본 스키마를 보존하면서 두 시트의 차이를 다뤄야 한다. 두 시트 모두 사례 연번이 고유하므로 시트 접두사를 붙인 사례 ID와 원본 파일·시트·물리 행 위치를 함께 기록하면 원본 사례를 추적할 수 있다.

### Agent 기반 RAG 학습 지도 보완

Agent RAG 자료에 ReAct Agent의 반복 Tool 호출, 독립 Tool의 병렬 호출, 미들웨어를 이용한 오류·호출 제한, 승인 인터럽트 개념을 추가했다. 문서에서는 노트북에서 확인한 구현과 부분 구현, 설계·확장 아이디어를 구분했다.

## 아직 확인하거나 복습할 것

- SIF 원본의 이용 조건을 확인하고 임베딩·색인 및 외부 배포가 허용되는 범위를 결정해야 한다.
- 평가 질문 20개의 `expected_case_ids`가 비어 있어, 실제 코퍼스가 정해진 뒤 원문과 질문의 관련성을 사람이 검토해 라벨링해야 한다.
- 기본 검색과 용어 확장 검색의 Hit@k·MRR 비교는 아직 수행하지 않았다.
- SIF 사례의 PostgreSQL 적재와 벡터 검색은 아직 완료되지 않았다.
- Agent 학습 지도의 승인 인터럽트는 부분 구현으로 분류되어 있다. 정책 설정과 실행 재개 흐름이 완전히 연결되는지는 추가 확인이 필요하다.
