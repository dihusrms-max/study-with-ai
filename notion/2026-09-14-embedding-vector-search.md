# 2026-09-14 일일 학습 보고 — 임베딩과 의미 기반 검색

## 오늘 새롭게 이해한 것

- 임베딩은 텍스트를 숫자 벡터로 변환해 검색·추천·RAG에 활용하는 방법이다.
- E5 계열 모델은 질문에는 `query:`, 검색 대상 문서에는 `passage:` 접두사를 붙여 역할을 구분한다.
- 질문 벡터와 문서 벡터의 코사인 유사도를 비교하면 단어가 완전히 일치하지 않아도 의미가 가까운 문서를 검색할 수 있다.
- 의미가 비슷한 문서 검색은 임베딩으로 처리하고, 가격·면적·지역 같은 숫자·범주 조건은 Pandas 필터링으로 처리하는 것이 적절하다.
- 로컬 임베딩 모델과 OpenAI 임베딩 모델은 검색 품질, 처리 속도, 비용, 한국어 이해도를 비교해 목적에 맞게 선택해야 한다.
- 검색 결과가 좋지 않으면 질문을 더 구체적으로 만들고, 문서의 제목·본문·불필요한 기호와 공백을 정제해야 한다.

## 아직 애매하거나 복습할 것

- 로컬 모델과 OpenAI 모델의 검색 품질을 동일한 평가 데이터로 비교하는 방법.
- 임베딩 검색의 적절한 유사도 기준과 검색 결과 평가 지표.
- 긴 문서를 여러 청크로 나누는 기준과 문서 단위의 최적 크기.
- 임베딩 검색과 Pandas 조건 필터를 결합하는 재사용 가능한 함수 구조.
- API 임베딩의 비용·속도·오류를 기록하고 관리하는 방법.

## 직접 해본 것

- 한국어 문장과 뉴스 문서를 SentenceTransformer로 벡터화했다.
- `query:`와 `passage:` 접두사를 사용해 질문과 문서 검색을 실습했다.
- 코사인 유사도로 뉴스 문서와 상품 데이터를 검색했다.
- 상품명·카테고리·설명을 하나의 검색 문장으로 결합해 상품 추천을 구현했다.
- 가격과 카테고리 조건을 Pandas로 먼저 필터링한 뒤 의미 기반 검색을 적용했다.
- OpenAI `text-embedding-3-small`로 문서와 질문을 임베딩하고 유사도를 비교했다.
- 오피스텔 실거래 데이터를 불러와 결측치·자료형을 확인하고 검색용 문서를 만들었다.
- 지역·가격 조건 검색, 단지별·층별 평균 월세 히트맵, 면적과 월세의 산점도를 구성했다.

## 오늘의 핵심 인사이트

- 임베딩은 “비슷한 의미를 찾는 검색”에 강하고, 정확한 숫자 조건은 구조화된 데이터 필터링이 더 안전하다.
- 좋은 검색 시스템은 모델만 선택하는 것이 아니라 문서 정제, 질문 구체화, 검색 결과 검증을 함께 설계해야 한다.
