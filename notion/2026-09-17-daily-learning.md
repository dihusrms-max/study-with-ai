## 오늘 이해한 내용

오늘은 RAG 시스템의 기본 구조와 벡터 데이터베이스를 학습했다.

RAG는 LLM이 질문에 바로 답하도록 하는 것이 아니라, 먼저 관련 문서를 검색한 뒤 검색된 내용을 근거로 답변하게 하는 방식이다.

```text
질문
→ 질문 임베딩
→ 벡터 DB에서 관련 문서 검색
→ 검색 결과를 Context로 구성
→ LLM에 질문과 Context 전달
→ 근거 기반 답변
```

## 핵심 개념

### 1. RAG가 필요한 이유

- LLM이 모르는 내용을 아는 것처럼 답하는 환각을 줄일 수 있다.
- 최신 문서나 사내 문서처럼 모델 학습에 포함되지 않은 자료를 사용할 수 있다.
- 어떤 문서를 근거로 답했는지 출처를 제시할 수 있다.

### 2. 임베딩과 유사도 검색

문서와 질문을 임베딩 모델로 숫자 벡터로 변환한다. 이후 질문 벡터와 문서 벡터의 유사도를 계산하여 관련 문서를 찾는다.

```text
문서 텍스트 → 임베딩 벡터
질문 텍스트 → 질문 벡터
두 벡터의 유사도 비교 → 상위 문서 선택
```

학습에서는 `text-embedding-3-small`과 코사인 유사도를 사용했다. 유사도가 높은 문서를 `top-k` 방식으로 선택하여 Context에 넣는다.

### 3. 벡터 DB

문서가 많아지면 모든 문서와 질문을 매번 직접 비교하기 어렵다. 벡터 DB는 문서를 색인하고, 가까운 벡터를 빠르게 검색한다.

학습한 도구:

- ChromaDB
- Qdrant
- HNSW 기반 근사 최근접 검색

문서에는 본문뿐 아니라 제목, 카테고리, 출처 URL과 같은 메타데이터도 함께 저장한다.

### 4. 메타데이터 필터링

벡터 유사도만 사용하는 것이 아니라 조건을 함께 적용할 수 있다.

```text
질문과 의미가 비슷한 문서
+ 특정 카테고리
+ 특정 단어 포함
+ 특정 출처나 날짜
```

예를 들어 `카테고리 == "경제"`인 문서만 검색하거나, 본문에 특정 단어가 포함된 문서만 검색할 수 있다.

## 오늘 직접 확인한 것

- CSV 뉴스 데이터를 문서 목록으로 변환했다.
- 문서에 임베딩을 적용했다.
- Chroma 컬렉션을 생성하고 문서와 메타데이터를 저장했다.
- 질문을 입력하여 유사 문서를 검색했다.
- 저장된 벡터 DB를 다시 불러왔다.
- 메타데이터와 본문 조건으로 검색 결과를 제한했다.
- KLUE MRC 데이터셋으로 질문, 검색 Context, 정답을 비교했다.

## 오늘의 한 문장

RAG는 LLM의 답변 능력에 검색 시스템을 결합하여, 외부 문서를 근거로 답변하게 만드는 구조이다.
