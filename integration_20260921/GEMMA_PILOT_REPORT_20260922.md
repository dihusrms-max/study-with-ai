# 통합 v2 Gemma API 진단 — 2026-09-22

결론: 실행 및 응답 형식은 정상이다. 근거문구 품질 문제가 확인되어 실제 모델 200건 확대는 보류한다. 최종 제출 성능이 입증된 상태가 아니다.

## 수정 및 검증

- v1 소스와 ZIP을 보존하고 candidate_v2에 수정본을 만들었다.
- 응답 복구의 각 단계가 끝날 때 검증된 성공 결과를 저장한다. 다음 복구 요청에서 엔진이 종료되는 경우에도 성공분이 보존되도록 수정했다.
- 엔진 종료 회귀 테스트와 API 어댑터 테스트를 포함한 15개 테스트 통과.
- C/D/E 각각 개발 200건 mock 형식·원문 근거·ID 순서·이어 실행 동일성 검증 통과.
- API 어댑터는 제출 ZIP 밖의 run_gemma_pilot.py에 두었다. 기존 Gemma 러너의 설정/병렬 호출 기반, experiment_manager의 세션·이벤트 기록, 예산 및 요청 동일성 도구를 재사용했다. API finish_reason과 실제 토큰 사용량을 보존한다.

API에서 토크나이저를 직접 사용하지 않아 입력 예산은 보수적인 문자 수 추정으로 잡았다. 이는 제출용 vLLM의 정확한 토큰 계산과 다르다. 동시 요청은 1개였다. 이번 시간만으로 서버 병렬 처리량을 확정할 수 없다.

## 로컬 정답 대조

기존 evaluate_dev200_run.py의 metrics 함수를 사용했다. 기준 정답과 데이터의 SHA-256은 evaluation.json에 기록했다. 정답 및 원본 데이터는 수정하지 않았다.

- TP 14, FP 1, TN 273, FN 0.
- 유일한 불일치: PPS-DEV-09의 v24. 정답 0, 모델 1.
- 정답 양성이 있는 항목은 v1~v9뿐이다. 이 12건으로 나머지 항목의 재현율을 판단할 수 없다.
- 기존 산식의 24항목 macro-F1은 0.375다. 표본에 양성이 없는 항목은 F1=0으로 집계되므로 전체 200건 점수나 공식 대회 점수와 비교하면 안 된다.
- 사용자 원본·팀원 원본을 이번 API 시험에서 함께 실행하지 않았으므로 통합으로 성능이 개선됐다는 결론은 낼 수 없다.

## 근거 누락 6개

근거가 필요한 양성 판정 15개 중 9개만 최종 원문 근거가 남았다. 아래 6개는 모델이 문자열을 반환했으나 원문 부분문자열 검증을 통과하지 못했다. 오탐인 v24도 이 집계에 포함된다.

| 공고 | 항목 | 확인한 형태 |
|---|---|---|
| PPS-DEV-05 | v3 | 원문과 다른 문자 포함 |
| PPS-DEV-05 | v8 | 말줄임표로 문구 생략·결합 |
| PPS-DEV-08 | v6 | 원문과 다른 표현 |
| PPS-DEV-09 | v9 | 원문과 다른 표기 |
| PPS-DEV-09 | v24 | meta와 본문을 요약·조합 |
| PPS-DEV-11 | v8 | 말줄임표로 문구 생략·결합 |

원문 검증을 느슨하게 하거나 누락을 임의로 채우지는 않았다. 원래 모델 근거와 분류는 evidence_analysis.json에 보관했다. 형식 PASS는 근거가 모두 확보됐거나 의미상 정답이라는 뜻이 아니다.

3. 같은 소량 표본과 별도 확인 표본에서 근거 누락 및 오탐 변화를 확인한 후 원본 두 개와 통합본의 200건 비교를 진행한다.
4. 실제 제출용 vLLM/GPU의 모델 로딩·시간·메모리는 별도로 검증한다.
