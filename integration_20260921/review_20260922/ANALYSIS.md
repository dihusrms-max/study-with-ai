## 확인된 문제 및 주의할 동작

### 1. 복구 중 엔진 종료 시 현재 배치의 성공 결과가 저장되지 않음 — 재현됨, 수정 우선

`pipeline.py:136`에서 모든 복구 모드를 끝낸 뒤 `pipeline.py:162`부터 성공 결과를 저장한다. `response_protocol.py:152`에서 엔진 종료 예외가 발생하면 이 저장 단계에 도달하지 못한다.

별도 테스트 러너로 두 건 중 한 건의 primary 응답은 정상이고 다른 건만 실패하게 한 뒤 compact 복구에서 EngineDeadError를 발생시켰다. 성공 응답은 1건이었으나 checkpoint의 rows는 0건이었다. skip_failures 켬/끔 모두 동일했다. 이전에 저장한 배치까지 잃는 것은 아니며, 현재 배치의 성공 건은 재추론이 필요하다.

권장 조치: 모드별 성공 판정을 검증하여 먼저 저장하거나, 치명적 예외를 다시 발생시키기 전에 이미 확정한 결과를 저장한다. 이를 확인하는 회귀 테스트를 추가한다.

### 2. 규칙 OFF는 최종 덮어쓰기만 끔 — 정적 확인

`retrieval_core.py:629`에서 항상 `support.analyze`를 호출하고 결과를 모델 입력에 포함한다. `decision_support.py:411`의 적용대상이 아닌 항목과 `:412`의 명시조건 보정후보에는 항목별 판정 후보가 들어 있다.

따라서 D는 '규칙 영향 없는 검색 전용' 후보가 아니다. D와 E의 차이는 최종 강제 덮어쓰기뿐이다. 순수 검색의 효과를 측정하려면 규칙에서 나온 판정 제안과 객관적 사실 추출을 추가로 분리해야 한다. 현재 README에도 이 범위는 명시되어 있다.

### 3. 규칙 ON은 양성 추가뿐 아니라 음성 강제 적용 범위도 큼 — 실행 확인

개발 200건에 규칙 분석만 수행했다. 양성 후보 합계는 148개 항목이었다. 그러나 v24에서는 200건 중 196건에 value=0 보정 후보가 생성됐다. 이는 `decision_support.py:406`의 명시적 불일치 후보가 없으면 v24를 0으로 두는 동작 때문이다. 이 중 원래 모델이 양성으로 판정한 건이 몇 개인지는 모델 추론을 하지 않았으므로 알 수 없다.

기존 mock의 전항목 0 출력은 0→1 변화만 드러낸다. 실제 모델의 1→0 변경 영향은 검증하지 못한다. 규칙을 켜려면 항목별 변경 방향, 정답 비교, 근거 적합성을 함께 평가해야 한다. 코드에 들어 있는 기준의 법적 타당성을 이번 분석으로 검증한 것은 아니다.

### 4. 근거 없는 양성이 형식 PASS로 저장될 수 있음 — 재현됨, 품질 한계

primary가 비어 있고 compact에서 v1=1을 반환하는 테스트를 수행했다. 최종 CSV는 v1=1, e1 빈칸이며 format_validation=PASS였다. 테스트 두 건 모두 positive_items_without_quote에 집계됐다.

이는 `parse_flags`가 판정값만 복구하고 `make_row`가 근거 부재를 빈칸으로 처리하는 설계다. 규칙 위반 형식이라고 단정할 수는 없지만, 형식 검증 통과가 판정의 근거 확보를 뜻하지 않는다. 자동으로 0으로 바꾸는 것도 정확도를 떨어뜨릴 수 있으므로 양성 항목의 근거 추가 추론 또는 별도 품질 평가가 필요하다.

### 5. 이어 실행 보고서는 누적 성능 보고서가 아님 — 재현됨

2건을 compact로 복구한 실행에서는 retry_records=2였다. 완료된 체크포인트로 이어 실행하자 같은 보고서가 retry_records=0으로 덮어써졌다. resumed_records=2는 남아 있다. 실행 시간과 응답 진단도 이번 호출 기준이다.

현재 코드는 판정 행과 규칙 변경 기록만 누적한다. 전체 처리 비용을 비교할 때 재개 후 보고서 하나만 사용하면 과소집계한다. 실행 이력별 보고서를 보존하거나 누적 지표와 이번 실행 지표를 구분해야 한다.

### 6. 출력·체크포인트 사전검사가 모델 로딩 이후임 — 정적 확인

`script.py:60`에서 VLLMRunner를 생성한 뒤 `pipeline.run`의 출력 충돌·체크포인트 검사를 한다. 이미 완료된 결과의 재개나 설정 불일치에서도 큰 모델을 먼저 로드한다. 실제 GPU 실행 시간을 이번 검토에서 측정하지는 않았다.

권장 조치: 경로·체크포인트 사전검사를 모델 생성 전으로 이동하고, 이미 전건 완료된 경우 추론기를 로드하지 않는다.
