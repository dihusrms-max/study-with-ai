# 통합 후보 v2 — 2026-09-22

사용자 베이스라인의 입력 검사·실행 옵션을 유지하고, 팀원의 검색·응답 복구·원문 근거 검증을 연결한 후보입니다. 기본 설정은 법령 검색 사용, 규칙에 의한 최종 판정 덮어쓰기 미사용입니다.

소량 Gemma API 진단을 수행했지만, 전체 정확도와 제출용 GPU 실행은 아직 검증하지 않았습니다. 이 ZIP은 통합 후보이며 최고 점수를 확인한 최종 제출본이 아닙니다.

## 실행

평가 환경에서 제공하는 데이터·모델을 지정하고 ZIP 루트의 진입점 `python script.py`를 실행합니다.

경로는 `PPS_DATA_DIR`, `PPS_OUTPUT_DIR`, `PPS_MODEL_DIR` 또는 `--data-dir`, `--output-dir`, `--model-dir`로 설정합니다. 기본 경로는 `./data`, `./output`, `/opt/models/gemma-4-26B-A4B-it`입니다. 실제 모델은 로컬 디렉터리를 사용하며 네트워크에서 모델을 받지 않습니다. 추론은 기존 코드와 같은 vLLM 구조화 출력 API를 사용합니다.

검색 모드에는 데이터 폴더의 `항목표.json`, `법령패키지/법령/*.txt`, `법령패키지/중기부고시/중기부고시_경쟁제품_세부품명.csv`가 필요합니다. 입력 기본값은 `test.jsonl.gz`입니다. 이 자산은 ZIP에 중복 포함하지 않습니다.

모델 없는 점검:

```text
python script.py --mock --data-dir DATA --input DEV.jsonl.gz --output-dir output/mock_check
```

`PPS_MODEL_DIR`가 설정된 서버 모드에서는 mock, 입력 변경, limit, skip-failures를 허용하지 않습니다. 로컬 점검 때 해당 변수를 해제해야 합니다.

## 비교 설정

| 설정 | 실행 옵션 | 동작 |
|---|---|---|
| C | `--pipeline baseline` | 사용자 프롬프트·문서 선택 + 엄격한 응답 복구·근거 검증 |
| D (기본) | `--pipeline retrieval` | 팀원 법령·품목 검색 및 문서 선택 추가 |
| E | `--pipeline retrieval --rule-corrections` | D + 규칙에 의한 최종 판정 덮어쓰기 및 변경 기록 |

C는 사용자 원본과 동일한 실행 결과를 보장하는 옵션이 아닙니다. 엄격한 실패 처리와 응답 복구, 근거 검증, 팀원 러너의 thinking 비활성화가 적용됩니다. D에서도 팀원 보조 모듈이 추출한 사실·조건은 프롬프트에 들어갑니다. `--rule-corrections`는 최종 판정 덮어쓰기만 제어합니다.

기존 옵션 `--quantization`, `--gpu-mem`, `--tp`, `--chunk`, `--max-chars`, `--max-tokens`, `--limit`, `--mock`을 지원합니다. `--doc-chars`는 `--max-chars`의 별칭입니다. 기본 문서 예산은 C 4,000자, D/E 14,000자입니다. 출력 토큰 기본값은 사용자 원본의 1,536, chunk는 128입니다. 복구 모드는 각각 768토큰을 사용합니다.

## 저장과 이어 실행

- 완전한 실제 추론 결과만 `submission.csv`에 기록합니다. mock 결과는 `mock_submission.csv`에 기록합니다.
- 성공 건은 `checkpoint.json`에 정수 판정값으로 저장합니다. mock은 파일명에 `mock_`가 붙습니다.
- 기존 출력이 있으면 자동 재사용하지 않습니다. 동일 옵션으로 `--resume`을 추가하거나 새 출력 폴더를 사용합니다.
- 이어 실행은 입력 내용·순서, 코드, 참조 자산, 추론 설정이 모두 같아야 합니다. 같은 모델 디렉터리 내부의 가중치 교체까지 탐지하는 것은 아닙니다.
- 같은 배치 안에서 일부 건이 실패해도 성공 건은 보존합니다. 기본 설정은 실패 시 중단하고 완료된 제출 CSV를 만들지 않습니다.
- `--skip-failures`는 로컬 부분 평가용입니다. 실패가 남으면 `partial_submission.csv`와 실패 ID를 저장하고 종료 코드 2를 반환합니다. 이후 `--resume`하면 누락 건만 재시도합니다.
- `run_report.json`에 복구 횟수·실패·미처리 ID 등을 기록합니다. `rule_changes.json`에는 규칙으로 변경한 항목의 적용 전후 판정·근거·사유가 기록됩니다.

## 구성과 의존성

- `baseline_core.py`: 사용자 원본 코드 보존 모듈.
- `retrieval_core.py`: 팀원 검색·프롬프트·vLLM 러너·근거 검증. 기존 실행 루프를 제거하고 중복 JSON 키 거부 및 러너 옵션을 보강했습니다.
- `response_protocol.py`, `decision_support.py`, `qualification_support.py`: 팀원 모듈.
- `pipeline.py`: 공통 실행·복구·이어 실행·판정 변경 기록.
- `script.py`: 사용자 CLI를 바탕으로 한 진입점.

팀원의 외부 `baseline/p003_script.py`에 의존하는 `run_api.py`, 결과 렌더링 및 사후 CSV 수정 도구는 제출 런타임에서 제외했습니다. 이 ZIP은 API 평가 도구를 포함하지 않습니다. 추가 pip 의존성을 도입하지 않았으며 실제 추론에는 제공 환경의 vLLM 및 관련 모델 패키지가 필요합니다.

## 검증 결과

실패·복구·부분 배치·이어 실행·근거 처리 관련 단위 테스트 15개를 통과했습니다. C/D/E 각각 개발 데이터 200건에서 49열 형식과 개별 원문 근거 검사, 입력 순서, 이어 실행 결과 동일성 검증을 통과했습니다. mock에서 E가 148개 판정을 바꾼 것은 규칙 실행 확인이며 정확도 지표가 아닙니다.
