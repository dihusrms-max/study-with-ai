# 브랜치·병합 규칙

- `main`은 항상 제출 가능한 상태로 유지하며 직접 커밋하지 않는다.
- 작업 브랜치는 `exp/<번호>-<짧은설명>` 형식을 사용한다.
- 브랜치 하나는 실험 하나만 다룬다. 실험 대장에 한 줄을 먼저 만든다.
- PR에는 변경 목적, 변경 항목, dev 점수 전후, 오탐·미탐 변화, 검증 결과를 적는다.
- 리뷰어 1명 이상이 공통 채점기와 제출 검증기를 직접 실행한 뒤 승인한다.
- dev 항목별 F1 하락이 없고, 새 무작위 표본의 오탐이 늘지 않으며, 형식 검증을 통과해야 병합한다.
- 특정 공고 ID 하드코딩과 dev 사례 맞춤 예외는 금지한다.
- 새 규칙은 가능하면 환경변수 스위치로 켜고 끌 수 있게 한다.

## 커밋 예시

`EXP-012 v9 모델 오탐 제외: dev v9 0.71→0.80, 회귀 없음`
