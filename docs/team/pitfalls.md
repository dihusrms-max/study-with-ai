# 함정·주의사항

- 자가라벨을 dev·골든셋처럼 반복 사용하지 않는다. 다음 라운드는 새 표본에서 시작한다.
- 라벨러가 과다 양성인 항목의 다수결을 공식 정답처럼 사용하지 않는다.
- 부재탐지 항목은 LLM 라벨러가 같은 방향으로 틀릴 수 있으므로 사람 또는 심판 확인 없이 규칙에 반영하지 않는다.
- `.work`의 라벨·원문·근거문구를 팀 저장소에 복사하지 않는다. 공유할 때는 방법론과 집계 요약만 남긴다.
- FP/FN 원시 건수만 합산하지 않는다. 표본 조건과 source를 구분하고 FP Rate·FN Rate를 함께 본다.

- 원문 데이터, 법령 스냅샷, API 키, `.env`, zip 파일은 저장소에 커밋하지 않는다.
- dev 점수만으로 일반화 성능을 단정하지 않는다. 가능하면 무작위 표본 오탐 감사를 함께 한다.
- 후보 간 점수는 동일한 데이터, 채점기, 모델 설정, 프롬프트 버전으로 비교한다.
- 라벨이 겹치고 불일치하면 코드에 임의 반영하지 말고 사람의 최종 결정을 기록한다.
- 제출 파일을 수동으로 수정하지 않는다. 태그의 코드에서 빌드한다.
- 개인 PC 경로, 특정 공고 ID 예외, 실행하지 않은 점수는 코드와 문서에 넣지 않는다.
