## 2. 빠른 개선 전략

목표는 짧은 시간 안에 전체 Prompt를 다시 쓰는 것이 아니라, FP가 큰 항목 하나의 오탐을 줄여 Macro F1을 올리는 것이다.

### 우선순위

1. v13: FP 85, FN 0 — 재현율 유지와 오탐 감소
2. v17: FP 52, FN 3 — 적용 대상과 예외 명확화
3. v21: FP 26, FN 4 — 공동수급 적용 조건 분리
4. v24: FP 29, FN 4 — 문서·메타 필드 비교 절차 명확화
5. v2, v6, v8, v10, v11, v14 — 미탐 중심 후속 개선

RAG, 20,000건 self-labeling, 파인튜닝은 위 단일 항목 Prompt 실험이 안정화될 때까지 보류한다.

## 3. 실행 절차

### 단계 A 기준선 변동 확인

- API 10건을 동일 조건으로 3회 실행한다.
- temperature, max_tokens, 입력 순서, 동시성, timeout, retry를 고정한다.
- 10건 전체 판정 일치율과 항목별 변경 수를 기록한다.
- 변동이 크면 v13 Prompt 실험을 시작하지 않고 API 조건을 먼저 점검한다.

### 단계 B v13 단독 Prompt

공통 Prompt는 유지하고 v13 판정 지침만 추가한다. 지침에는 다음을 포함한다.

- 해당 공고가 실제 적용 대상인지 먼저 확인
- 단순히 중소기업 관련 표현이 있다는 이유만으로 위반 판정하지 않음
- 의무 제한과 권장·우대 표현을 구분
- 판로지원 관련 예외가 있으면 예외 조건을 우선 확인
- 위반 판정에는 적용 대상과 위반 조건이 함께 충족되어야 함

법령의 구체적인 조건은 항목표와 사람이 확인한 기준만 사용하며, 확인되지 않은 법률 해석을 Prompt에 임의로 추가하지 않는다.

### 단계 C 검증 게이트

각 후보는 다음 순서를 통과해야 한다.

```text
1건 JSON/evidence 확인
→ 10건 형식·변동 확인
→ dev 200건 실행
→ 24개 항목 전체 회귀 확인
→ 사람 검토
→ 제출 후보 승인 또는 폐기
```

## 4. 채택 기준

후보 Prompt는 다음 조건을 모두 만족할 때만 채택한다.

- 전체 Macro F1이 동일 실행 기준선보다 높음
- 목표 항목의 FP 또는 FN이 개선됨
- 다른 항목의 F1이 뚜렷하게 하락하지 않음
- JSON 오류와 누락 항목이 없음
- evidence 원문 검증 오류가 없음
- 실행시간이 허용 범위 안에 있음
- 사람이 변경 내용을 검토함

API 점수 상승만으로 DACON 점수 상승을 보장한다고 판단하지 않는다. 실제 제출은 V0 점수 0.2136954413을 유지한 상태에서 별도 후보로 진행한다.

## 5. 이중 검토 체크리스트

다른 PC 또는 리뷰어는 아래 항목을 독립적으로 확인한다.

- [ ] V0 실제 점수와 V1 실제 점수가 혼동되지 않았는가
- [ ] API dev 점수를 대회 점수로 해석하지 않았는가
- [ ] P001-R 상승을 개선 효과로 채택하지 않았는가
- [ ] 기준선 반복 조건이 동일했는가
- [ ] 이번 Prompt 변경 대상이 v13 하나뿐인가
- [ ] v13의 적용 대상·위반 조건·예외 조건이 구분되어 있는가
- [ ] FP와 FN이 기존 결과와 비교되어 있는가
- [ ] 다른 23개 항목의 회귀를 확인했는가
- [ ] JSON, evidence, 실행시간 검증을 수행했는가
- [ ] API 후보를 실제 제출 코드에 바로 반영하지 않았는가
- [ ] V0 fallback과 제출 전 후보 승인 절차를 유지했는가

## 자가라벨링 독립 검증 라운드

dev 200건은 빠른 비교용으로만 사용하고, Prompt 후보의 일반화 근거는 새 독립 표본으로 별도 확인한다.

```text
판정카드 24장 확인
→ 이전 사용 ID 제외 후 seed 고정 무작위 추출
→ 저가 모델 2종 항목 라벨
→ 합의 셀과 불일치 셀 분리
→ 불일치 셀 심판
→ FP/FN 원인 유형화
→ 이전 확정 셀 회귀 0 확인
```

독립 라운드 기본안은 2,000건(무작위 1,500건 + 희소 항목 보강 500건)이다. 실제 비용과 표본 조건은 실행 전에 기록하고 승인한다.

라벨러 신뢰도는 항목별로 산출한다. 과다 양성 항목과 부재탐지 항목은 라벨러 다수결만으로 확정하지 않고 사람 또는 상위 심판 검토를 거친다.

자가라벨 원문·공고 본문·근거문구는 `.work` 또는 개인 보관 영역에 두고 팀 저장소에는 방법론·스키마·집계 결과·해시만 공유한다.

## 최종 제안

가장 빠른 다음 행동은 API 10건 3회 반복으로 변동성을 확인한 뒤, 안정적일 경우 v13 단독 Prompt를 dev 200건에서 검증하는 것이다. v13 후보가 안정적으로 개선되면 같은 방식으로 v17, v21, v24를 진행한다. V0는 새 후보가 실제 DACON 점수로 검증될 때까지 유지한다.
